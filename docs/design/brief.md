# Rex Browser design brief

Starting point: existing brand, explicitly selected Alephic Product / Workbench.
This supersedes the pending no-brand entry question.

Feels like: quiet, precise, practical (from selected Product system). Must not:
generic dashboard decoration, orange chrome, animated terminal output, controls
competing with work. Constraints: Geist/Geist Mono; Product light and dark
palettes; compact Ink toolbar; Forest selection; no restyling terminal-authored
ANSI colors. Native browser app, no framework migration required.

| View               | Job                                                             | Real content source                                                         |
| ------------------ | --------------------------------------------------------------- | --------------------------------------------------------------------------- |
| Session navigation | Find host, session and named tab                                | Rex metadata: Mini/Spark; envoy, Reviews, Tools                             |
| Tiled workspace    | Read and target the selected pane                               | Rex layout tree; terminal titles; synthetic terminal output clearly labeled |
| Submit / new tab   | Send text with clear destination and feedback; open a shell tab | Implemented local UI behavior and scratch QA                                |

Open: desktop-first versus full phone interaction. Brand is chosen; structural
variations within Product still need visual review. Functional fixes in this
revision precede the visual redesign; no visual direction has been silently
selected.
